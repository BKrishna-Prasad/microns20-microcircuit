# Reproducibility

## Installation

The preferred public installation should eventually be:

```bash
git clone <repository-url>
cd microns20-microcircuit

conda env create -f environment.yml
conda activate microns20

pip install -e .
```

## Structural tests

From the repository root:

```bash
python -m pytest -q
```

## Pipeline execution

The structural notebooks can be executed in order using the repository script:

```bash
python scripts/execute_pipeline_notebooks.py
```

## CAVE authentication

The structural pipeline requires authenticated access to MICrONS through CAVEclient.

A CAVE token must **not** be written into:

```text
configs/
notebooks/
src/
provenance/
README.md
git history
```

### First-time token setup

Activate the project environment:

```bash
conda activate microns20
```

Start Python:

```bash
python
```

Then run:

```python
from getpass import getpass

from caveclient import CAVEclient

client = CAVEclient()
client.auth.get_new_token(open=True)

token = getpass("Paste your CAVE token: ")
client.auth.save_token(token=token)
```

Follow the authentication page or terminal instructions produced by `get_new_token()`, generate the token, and paste it at the prompt.

CAVEclient saves the token by default at:

```text
~/.cloudvolume/secrets/cave-secret.json
```

The file is outside the cloned repository and contains the token under the `token` key.

Once saved, future `CAVEclient` instances automatically load this token; the project therefore does not need to pass credentials through configuration files or notebook code.

### Verify authentication

Without displaying the token, run:

```bash
python -c "from caveclient import CAVEclient; c=CAVEclient(); print('CAVE authentication available:', c.auth.token is not None)"
```

Expected output:

```text
CAVE authentication available: True
```

If authentication has already been configured on the machine, no new token needs to be created.

### Project configuration

Authentication and scientific configuration are separate.

The project's MICrONS datastack, materialisation, skeleton version, biological filtering rules and selection settings are defined in:

```text
configs/project.yaml
```

After authentication is configured, the structural pipeline can be run from the repository root with:

```bash
python scripts/execute_pipeline_notebooks.py
```

## Functional NDA access

The future functional-data stage will require NDA v8 access.

Database host, username and password should be supplied through environment variables or local DataJoint configuration.

They must not appear in:

```text
configs/
notebooks/
provenance/
git history
```

## Allen model

The Allen model is currently kept under:

```text
data/external/allen_cell_types/487245719/
```

for local development.

For the public repository, prefer a documented retrieval step instead of committing the downloaded directory unless redistribution has been explicitly reviewed.

The required local contents are:

```text
fit_parameters.json
model_metadata.json
reconstruction.swc
modfiles/*.mod
```

## NEURON mechanisms

Allen NMODL mechanisms are compiled with:

```bash
nrnivmodl modfiles
```

Generated `x86_64/` mechanism-build directories are platform-specific.

## Simulation runs

The `runs/` directory is generated.

A public release should keep:

- simulation config;
- synapse parameter files;
- code;
- compact summary CSVs;
- selected figures.

It should not need to commit every HDF5 output generated by every run.
